# 🔄 Phase 8.2: Semantic Replay Worker Architecture

## 1. System Overview
The **Semantic Replay Worker** closes the feedback loop between runtime query execution and offline contract refinement. It continuously ingests production audit logs from the **Phase 8.1 Semantic Firewall**, replays allowed and audited queries against historical DuckDB data snapshots, injects AST mutation operators, and flags **"Silent Survivors"**—queries that passed the firewall but failed empirical mutation testing due to contract underspecification.

```

|  Text-to-SQL Agents /  | ==============================> | SRE Audit Trail Queue  |
|   BI Query Gateways    |    (JSON / Kafka / Datadog)     |  (Redis / SQS / Kafka) |
+------------------------+                                 +------------------------+
            |                                                           |
            | Evaluate API (Phase 8.1)                                  | Batch Ingest
            v                                                           v

+------------------------+                                 +------------------------+

## 2. Core Operational Workflow

### Step 1: Log Ingestion & Sampling
- Worker listens on an async queue (Redis Streams, AWS SQS, or Kafka topic).
- Ingests structured audit traces generated by `_record_audit_trace()` containing:
  - `trace_id`, `timestamp`, `agent_id`, `metric_id`, `sql_hash`, `contract_version`, `violations`.

### Step 2: Empirical Data Snapshot Replay
- For sampled queries marked `ALLOW` or `AUDIT`, the worker loads the corresponding partitioned data snapshot into local DuckDB.
- Executes the base candidate SQL query to compute baseline metric output: $M_0$.

### Step 3: AST Mutation Stress-Testing
- Injects standard AST mutations:
  1. `FILTER_DROP`: Omit status, region, or boundary filters.
  2. `BOUNDARY_SHIFT`: Shift interval predicates (`>=` to `>`).
  3. `AGGREGATION_SWAP`: Swap primary aggregation operators (`SUM` to `AVG`).
  4. `GRAIN_DROP`: Drop grouping keys.
- Executes mutant queries $M_1, M_2, \dots, M_k$ on DuckDB.

### Step 4: Silent Survivor & Contract Gap Detection
- If mutant output diverges ($M_k \neq M_0$) on empirical data, but the current metric contract yielded **0 runtime violations**, the worker classifies the query as a **"Silent Survivor"** under the `MISSING_CONTRACT` taxonomy.
- Worker emits automated contract enhancement recommendations (e.g. *"Query omitted temporal filter `attribution_window_days <= 30`, which altered revenue by 14.2% on historical snapshot"*).

## 3. Worker Component Architecture

```
semantic_reliability/replay/
├── __init__.py

├── sampler.py         # Stratified query sampling by agent and metric

## 4. Key Value Proposition for Enterprise Data Teams
1. **Contract Auto-Tuning:** Turns passive query logs into active contract invariants without requiring manual rule authoring.
2. **Defect Pre-emption:** Catches edge-case logic failures before they manifest in board-level analytics reports.
3. **Agent Drift Monitoring:** Continuously tracks if fine-tuned or prompt-updated Text-to-SQL agents are degrading in semantic rigor over time.
