## 1. Executive Summary

Modern enterprise analytics and AI agent workflows suffer from a fundamental governance gap: **metrics are defined informally, maintained in fragmented codebases, and generated by AI agents without runtime guarantees.**

The **Semantic Contract Open Standard (SCOS)** establishes a vendor-neutral, declarative specification for defining business metrics. Unlike traditional semantic layer models that focus purely on query generation, SCOS defines **executable invariants, mutation tests, and runtime observability probes**.

## 2. Core Architecture

An SCOS document is a valid YAML or JSON artifact structured into four orthogonal layers:

```yaml
# 1. Identity & Governance Header
scos_version: "1.0.0"
id: "urn:scos:finance:net_revenue"
metric: "net_revenue"
version: "1.2.0"
owner: "finance-data@enterprise.com"
domain: "finance"
grain: "customer_month"
dialect: "bigquery"

# 2. Canonical Ground Truth
sql: |
  SELECT 
    customer_id, 
    DATE_TRUNC(transaction_date, MONTH) AS transaction_month,
    SUM(amount - coalesce(discount, 0) - coalesce(refund, 0)) AS net_revenue
  FROM `enterprise.finance.transactions`
  WHERE status = 'active'
    AND is_test_account = FALSE
  GROUP BY 1, 2

# 3. AST Semantic Invariants (Deterministic Static Guardrails)
invariants:
  population:
    required_filters:
      - "status = 'active'"
      - "is_test_account = FALSE"
    forbidden_filters:
      - "status = 'cancelled'"
  deduction:
    required_subtractions:
      - "discount"
      - "refund"
  temporal:
    timezone: "UTC"
    period_grain: "MONTH"

# 4. Statistical Reality Probes (Runtime Observability)
probes:
  population:
    - predicate: "status = 'active'"
      min_rate: 0.05
      max_rate: 0.25
  implications:
    - antecedent: "status = 'active'"
      consequent: "amount > 0"
      min_confidence: 0.99
  null_drift:
    - column: "customer_id"
      max_null_rate: 0.00
```

## 3. Layer Specifications

### 3.1 Identity & Registry Layer
- **`scos_version`**: Must be `"1.0.0"`.
- **`id`**: Canonical URN formatted as `urn:scos:<domain>:<metric_slug>`.
- **`version`**: Semantic Versioning (`MAJOR.MINOR.PATCH`) to track business metric evolution.
- **`grain`**: Declares the reporting dimensionality and entity level (`<entity>_<timeframe>`).

### 3.2 Canonical Representation Layer
- **`sql`**: The signed, human-authorized implementation of the metric. Serves as the ground-truth oracle for mutation testing, dry-runs, and replay workers.
- **`dialect`**: Target SQL dialect (`snowflake`, `bigquery`, `postgres`, `duckdb`, `databricks`, `redshift`).

### 3.3 Semantic Invariants Layer (Static Enforcement)
Invariants define relational algebra rules that any candidate query must satisfy:
- **`population.required_filters`**: AST predicates that must be logically present in the query `WHERE` tree.
- **`population.forbidden_filters`**: Predicates that must never appear (e.g. including churned customers in active revenue).
- **`deduction.required_subtractions`**: Expressions that must be subtracted from the additive sum.
- **`temporal.timezone`**: Declares default timezone semantics to prevent silent boundary drift.

### 3.4 Statistical Probes Layer (Runtime Observability)
Probes continuously monitor the underlying data warehouse to catch **"Silent Reality Drift"**:
- **Population Probes:** Ensure filter rates remain within historical confidence bounds.
- **Implication Probes:** Test logical business dependencies across attributes.
- **Null Drift Probes:** Ensure required join keys and identifiers do not degrade.

## 5. Conformance & Verification

A software system is **SCOS v1.0.0 Compliant** if it provides:
1. **Schema Validation:** Strict parsing of SCOS YAML/JSON against `scos-v1.schema.json`.
2. **Deterministic AST Invariant Enforcement:** Capable of validating SQL candidates without false positives on cosmetic formatting or commutative operations.
3. **Audit Evidence Generation:** Produces deterministic, verifiable SHA-256 evidence digests for all evaluation decisions.
