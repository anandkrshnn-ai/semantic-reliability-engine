Two parallel document trees with distinct purposes: `spec/` contains the machine- and human-readable contract definition — `SCOS_V1_SPECIFICATION.md` defines the four-layer metric contract (identity/governance, canonical SQL, AST semantic invariants, statistical probes) and `scos-v1.schema.json` is a JSON Schema Draft 2020-12 that enforces required fields (`scos_version`, `metric`, `owner`, `grain`, `sql`) plus enum-restricted dialects and URN patterns used by validators. `docs/` is an unstructured knowledge base organized by topic: architecture whitepapers (`ENTERPRISE_ARCHITECTURE_WHITEPAPER.md`, `ENTERPRISE_ARCHITECTURE_AND_CISO_WHITEPAPER.md`), security posture (`MCP_SECURITY_AND_THREAT_MODEL.md`), evaluation rigor (`BENCHMARK_METHODOLOGY.md`), phase-specific design notes (`PHASE_8_2_REPLAY_WORKER_ARCHITECTURE.md`, `RELEASE_NOTES_v*.md`), and strategic/operational manifestos (`SCOS_LAUNCH_MANIFESTO.md`, `SURVIVING_DEFECT_ANALYSIS.md`). There are no executable artifacts; consumers reference `spec/scos-v1.schema.json` as the conformance boundary and read `docs/*` for policy and design rationale.
