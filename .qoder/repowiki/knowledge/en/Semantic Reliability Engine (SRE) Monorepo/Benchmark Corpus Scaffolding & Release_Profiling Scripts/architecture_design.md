The scripts are standalone entry points (no shared library) organized by purpose into three groups. Corpus scaffolding: `scaffold_corpus.py` generates 8 development models under `benchmark_corpus/<id>/` (SQL, contract YAML, fixture CSV, dbt `schema.yml`, semantic assertions YAML), while `scaffold_holdout_corpus.py` moves top-level model dirs into `dev/` and creates 6 frozen holdout models under `holdout/`. Benchmarking runners: `run_two_engine_benchmark.py` executes the full 5-tier Baseline Ladder (syntax → minimal structural → realistic dbt suite → static SCOS AST → runtime relational oracle) over all dev+holdout models using DuckDB in-memory fixtures and writes a JSON scorecard; `profile_hybrid_escalation.py` profiles the HybridValidator's Tier-3/Tier-4 routing decisions across the same corpus and exports `hybrid_escalation_scorecard.json`; `test_unmutated.py` validates that all 14 unmutated ground-truth queries pass Tier 2. Release tooling: `create_release.py` posts a draft pre-release to GitHub via `urllib.request` from a markdown notes file, and `update_release.py` updates an existing release's `target_commitish` and body via the `requests`-based GitHub API. All scripts depend only on the installed `semantic_reliability` package plus DuckDB/pandas/rich; they read/write files relative to the repo root (`benchmark_corpus/`, `docs/`, `examples/assertions/`).
