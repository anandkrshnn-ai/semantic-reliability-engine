Two complementary entry points sit at the package root: `cli.py` defines a single Click group (`main`) with one command per workflow (`check`, `mutate`, `benchmark`, `benchmark-corpus`, `evaluate-agent`, `pr-comment`, `compile`, `probe`, `export-gym`, `audit-gym`, `bq-evaluate`, `dbt-check`, `mcp-serve`, `benchmark-replay`, `benchmark-live`, `audit-provenance`). Each command is thin — it parses options via `click.option`, lazily imports heavy submodules (e.g. `semantic_reliability.harness.*`, `semantic_reliability.benchmark.*`, `semantic_reliability.adapters.*`) to keep startup fast, orchestrates domain engines (`MetricCompiler`, `SemanticDriftDetector`, `MutationEngine`, `DuckDBFixtureRunner`, `QualityHarness`, `Reporter`, `SARIFExporter`, `ContractRegistry`, `ScosMcpServer`), and renders results through `rich.console`/`rich.table`. The `guardrail.py` module exposes a stateful `SemanticGuardrail` class whose constructor accepts a YAML file, directory of contracts, a `MetricDefinition`, or a dict; it builds an internal `ContractRegistry` + `SemanticEvaluator` and offers `verify()` returning a `GuardrailResult` dataclass and `intercept()` which raises `SemanticDriftException` on violation. The package `__init__.py` re-exports the public surface (`MetricCompiler`, `SemanticDriftDetector`, `MutationEngine`, `QualityHarness`, `MutationBenchmark`, `SemanticGuardrail`, `GuardrailResult`, `SemanticDriftException`), making this leaf the stable import boundary for consumers while keeping CLI-specific code separate from the library API.
