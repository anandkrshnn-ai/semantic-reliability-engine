Tests are organized as one flat pytest module per production subpackage under `tests/`, each importing the corresponding `semantic_reliability.*` package to exercise it end-to-end. Common patterns include: (1) `pytest.fixture` functions that build small in-memory DuckDB databases or write temporary YAML/CSV corpora via `tmp_path`; (2) CLI tests driven by Click's `CliRunner` invoking `semantic_reliability.cli.main` with subcommands like `compile`, `check`, `mutate`, `benchmark`, `export-gym`, `audit-gym`, `probe`, and `pr-comment`; (3) unit-style assertions on firewall decisions (`Decision.ALLOW/DENY/REQUIRE_REVIEW`), probe alert signals, benchmark evaluator reports, and MCP JSON-RPC responses; (4) shared fixture shapes such as `MetricDefinition` + `SemanticInvariants` + `PopulationInvariant` registered into a `ContractRegistry`. There is no shared conftest visible at this scope — each file self-contains its fixtures and imports.
