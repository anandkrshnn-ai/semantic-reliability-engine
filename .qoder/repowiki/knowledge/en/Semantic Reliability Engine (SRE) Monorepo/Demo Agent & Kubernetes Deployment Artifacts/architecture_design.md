Two complementary deployment artifacts share the `semantic_reliability` Python package as their runtime dependency. The `demo/` directory defines a self-contained example: `agent.py` bootstraps a local `ContractRegistry`, loads YAML metric contracts from `benchmark_corpus/dev` via `MetricCompiler`, and drives three validation scenarios (ALLOW / REQUIRE_REVIEW / ABSTAIN) through `ScosMcpHandlers.call_tool`. `Dockerfile` builds a non-root `appuser` image exposing port 8000 with a socket-based healthcheck; `docker-compose.yml` orchestrates two services on a shared bridge network — `scos-mcp-server` running `sre mcp-serve --contracts benchmark_corpus/dev --port 8000` and `analytics-agent-demo` depending on it. The `deploy/k8s/semantic_firewall_sidecar.yaml` defines a Kubernetes `Deployment` in the `analytics` namespace that co-locates a primary `text2sql-agent` container with an `sre-semantic-firewall` sidecar (`uvicorn semantic_reliability.firewall.main:app` on port 8080). The sidecar mounts metric contracts from a `ConfigMap` (`sre-metric-contracts`) at `/etc/sre/contracts` and is configured via `SRE_STRICT_MODE` (audit vs hard DENY) and `SRE_CONTRACTS_DIR`; liveness/readiness probes target `/health`. Prometheus scraping annotations are declared on the pod template.
